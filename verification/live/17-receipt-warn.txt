Two things worth knowing:

- **World-writable on an executed script is a real exposure**: any local account on the machine can now rewrite `run.sh`, and whatever runs it (CI, a hook) executes that content with the runner's privileges. The narrower fix for "the CI user needs to edit it" is `chgrp <ci-group> scripts/run.sh && chmod 775` — same edit access for CI, no write access for everyone else. Say the word and I'll switch it, or revert to 644.
- **Git won't carry this anyway.** `scripts/run.sh` is currently untracked, and even once committed git only records the executable bit — it stores this as mode `100755`. So the `777` exists on this working copy only; a fresh clone on the CI box lands at `755` (minus umask), and the CI user still won't be able to edit it. If the goal is CI-side editability, this needs to be set on the CI machine — a repo-side chmod won't get you there.
